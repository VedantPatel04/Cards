# Local development and deploying

## Local development

### API

```bash
docker compose up --build
docker compose exec web python manage.py setup_dev   # seed catalog + demo user
```

Django runs on `http://localhost:8000`. `setup_dev` prints demo credentials.

Interactive API docs (Swagger UI, Try it out enabled): [`http://localhost:8000/api/docs/`](http://localhost:8000/api/docs/)  
Raw OpenAPI schema: [`http://localhost:8000/api/schema/`](http://localhost:8000/api/schema/)

On Render, the same paths are on your API host — `https://<your-render-host>/api/docs/` (not the Vercel frontend).

### Frontend

```bash
cd frontend
cp .env.example .env          
npm install
npm run dev                   
```

See [workflows.md](workflows.md) for the full test and verification guide.

## Deploying

The `render.yaml` blueprint provisions the API and Redis on Render. Postgres is hosted on Supabase.

Required env vars (set in Render dashboard):

| Var | Notes |
|---|---|
| `DATABASE_URL` | Supabase session-pooler URL with `?sslmode=require` |
| `SECRET_KEY` | Generated by Render blueprint |
| `ALLOWED_HOSTS` | Exact Render hostname |
| `CORS_ALLOWED_ORIGINS` | Vercel frontend URL |

After deploying the frontend to Vercel (project root: `frontend/`, env `VITE_API_BASE_URL`), add the Vercel URL to `CORS_ALLOWED_ORIGINS` on Render.
